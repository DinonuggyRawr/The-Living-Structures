# Building The Living Structures from source

This is a Unity project, not a standalone C# application. Use the Unity Editor version recorded in `ProjectSettings/ProjectVersion.txt`. Both `Packages/manifest.json` and `ProjectSettings/` are important for a reproducible project. Do not upload Unity `Library`, `Temp`, or generated builds as normal source commits.

1. Clone/download the **source repository**, including `Assets`, `Packages`, `ProjectSettings` and `.meta` files.
2. Open the project in the matching Unity Editor. Import/restore the dependencies listed in the project's Package Manager manifest as required by Unity.
3. Ensure the Academy scene is first (index 0) in the Windows Build Profiles scene list. The scene may be generated by the Editor scene-builder scripts for older project baselines; do not rebuild an already customized scene without backing it up.
4. Run the complete EditMode test suite. Confirm user navigation, code editing, and Exit App in Play Mode.
5. For actual C11/WASM execution, use the project's Editor setup scripts to install the explicitly versioned Zig/Wasmtime toolchain, or stage the **already trusted, verified** local bundle. The compiler is not stored in Git.
6. Build Windows x64 to a folder outside the source directory and outside OneDrive where possible. Review the Phase 8 release-readiness report. Test the **exact** standalone output offline and on a clean machine, using multiple C11 exercises.
7. Review licensing for the **exact binaries that will ship** and the [security model](SECURITY.md). Only then consider attaching a complete ZIP of the player to a GitHub Release.

Do not equate an all-green EditMode run with a complete PlayMode, end-to-end, accessibility, license, or security verification. Student C executes as WebAssembly after the native compiler stage; the native compiler is **not** isolated from the Windows user's account.
